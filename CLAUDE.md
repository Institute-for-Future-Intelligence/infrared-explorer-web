# CLAUDE.md

## Development Rules

- **Do not start the dev server unless necessary.** Unless the user explicitly asks to run/start the app or needs the change verified in the real running app, do not automatically run commands that start a dev server such as `yarn start` / `npm run dev`. Prefer type-checking, building, or tests to verify changes.

- **When committing to git, only commit what was changed in the current session.** Do not run `git add .` / `git add -A` to stage the entire working tree. Only `git add` the files you actually modified in this session; leave any unrelated working-tree changes untouched and do not bundle them into this commit.

- **Do not commit to git on your own initiative.** Unless a plan explicitly states that each step should be committed as it is completed, do not run `git commit` without being asked. Finish the work and leave the changes staged/unstaged for the user to review and commit, unless the user (or the agreed plan) has told you to commit.

- **When deploying functions, never delete the `labProject*` functions.** The app repo (`infrared-explorer-app`) deploys its own functions codebase, `labprojects`, from its `functions/` folder to this same Firebase project: `labProjectCreate`, `labProjectList`, `labProjectGet`, `labProjectTurn`, `labProjectEdit`, `labProjectAttach`, `labProjectShare`, `labProjectOpenShared`, `labProjectCopy`, `labProjectCommunityList`, `labProjectDelete`, `labProjectQuota`, `labProjectConsent`, `labProjectDeleteAnonymousAccount` and `labProjectsOnUserDeleted`. They are not in this repo's source on purpose. If `firebase deploy` (directly or through `npm run deploy:functions` / `deploy:all`) asks whether to delete any function whose name starts with `labProject`, answer **No**; the rest of the deploy still goes ahead. Don't add `--force` to a functions deploy (it deletes without asking), and don't run `firebase functions:delete` on them even if the CLI suggests it.

- **The AI Project section (`src/labProjects/`, pages in `src/pages/labProjects/`, routes `/projects` and `/projects/:projectId`) is independent of the site's own AI code.** It shows the AI lab projects a user made in the mobile app and uploaded from it, reading everything through the app's `labProject*` callables above (the `labProjects` collection has no client rules). It must not import or call `src/services/ai.ts`, `src/components/aiChat/*`, the analyzer's Ask AI / AI Report tabs, `labReports` or `aiInbox`; its only shared ground with them is Firebase initialisation and sign-in. The files in `src/labProjects/core/` (except `math.ts` and the generated `aiSensors.ts`) are verbatim copies of the app repo's `src/lib/labProjects/` — edit them there and run `npm run sync:lab-core` (`scripts/sync-lab-core.mjs`, which also writes `core/SOURCE.md` with the source commit); never edit the copies in place. The user-visible name is "Experiments" (2026-10-16, the same in the app: "AI Project" became "Projects", then "Experiments"; at the same time the uploaded recordings, which the site and the app called "experiments", became "Recordings" on screen, so "My Experiments" is now "My Recordings"): the signed-in list at `/projects` is "My Experiments" (sidebar, its heading, breadcrumbs) and Community's tabs are "Recordings" and "Experiments". Only the words on screen changed: the code, types, routes, collections and callables keep `project` / `experiment` in their old senses. The route stays `/projects` because `public/.well-known/*` registers `/projects/*` as the app's deep link. A new project's stored title stays "Untitled Project" (the server names a project only while it carries that title); `core/empty.ts` `shownTitle()` shows it as "Untitled Experiment". Plan: the app repo's `docs/proposals/ai-projects-web.md`.

- **The analyzer's Ask AI and AI Report run on the app's AI flow (since 2026-10-19; `docs/analyzer-ai-app-flow-plan.md`).** They are about the current recording (`experiments/{expId}`) and nothing else: no lab project is created or bound, and there is no discussion area. What the model is told and how it is called is the app's, copied verbatim into `functions/src/labCore/` by `npm run sync:lab-core` (`prompt.ts`, `toolSchemas.ts`, `llm.ts`, `partialJson.ts`, `textDiff.ts`; the shims `config.ts`, `secrets.ts`, `store.ts` beside them are the website's) — edit those in the app repo's `functions/src/` and re-sync, never in place. The engine is `functions/src/recordingAi/` (callables `recordingAiTurn`, `editLabReport`, `clearRecordingAiThread`); the browser tools `look` / `run_code` are the Projects section's own (`src/labProjects/browserTools.ts`, `cloudTake.ts`, `overview.ts`, `render.ts`, `sandboxHost.ts`, `codeState.ts`), which the analyzer may import together with `MarkdownView`, `components/Lightbox`, `components/PictureCard`, `components/ConsentDialog`, `components/DocEditorModal`, `consent.ts`, `exportReport.ts` and `core/*` — but not `labProjects/api.ts`, `runner.ts` or `store.ts` (those are the project's). The pages are `src/pages/experimentAnalyzer/ai/` (`recordingAiRunner.ts`, `RecordingThread.tsx`, `RecordingReport.tsx`, `RecordingReplies.tsx`) over `src/services/recordingAi.ts`. An Ask AI thread lives at `experiments/{expId}/aiThreads/{uid}`, a report run at `experiments/{expId}/aiReportRuns/{runId}` (7-day TTL), the report in `labReports/{id}` with `images[]` and, as before, in the experiment's `aiReport*` fields and `labReportId`. The old `answerExperimentQuestion` / `generateLabReport` callables stay deployed for older app builds until retired; nothing on the site calls them.
